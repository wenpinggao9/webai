# 目录规范

工程分为三个区域：**业务资产**、**框架内核**、**运行时工作区**。

---

## 三区总览

| 区域 | 路径 | 维护方 | 是否协作传递 |
|------|------|--------|--------------|
| 业务资产 | `business/` | QA 主维护，研发可回填 | 是 |
| 框架内核 | `core/`、`prompts/`、`api/` | QA | 是（代码） |
| 运行时工作区 | `output/` | 框架自动生成 | 否 |

依赖方向：`run.py` / `api/` → `core/agent.py` → `core/*`；`core/` 通过 `BusinessLoader` 读取 `business/`，不硬编码业务路径。

---
#### 两种跑测模式

```bash
# 默认：每次 LLM 动作规划 → 执行 → 覆盖写入 actions/<文件名>_actions.json
python run.py business/tiku/tiku_video/大学增加前审/cases/前审12-test.md

# 预规划：读取 actions/<文件名>_actions.json，跳过 LLM 规划，不改写 actions 文件
python run.py business/tiku/tiku_video/大学增加前审/cases/前审12-test.md --from-actions
```

## 根目录

```
ui_automation/
├── run.py                  # CLI 入口
├── config.yaml             # 全局：LLM、Playwright、runner、delivery.accel 等
├── requirements.txt
├── Dockerfile
├── pytest.ini
├── business/               # 业务资产（见 business/README.md）
├── core/                   # 框架内核
├── prompts/                # LLM 提示词（可编辑）
├── api/                    # HTTP / 远程 Agent 接入
├── tests/                  # 框架自测
├── tools/                  # 辅助脚本（export_handoff、prompt_replay）
├── docs/                   # 文档
└── output/                 # 运行时产物（gitignore）
```

### 根目录执行方式

| 入口 | 命令示例 | 说明 |
|------|----------|------|
| CLI 跑用例 | `python run.py business/tiku/tiku_video/大学增加前审/cases/前审12-test.md` | 默认：LLM 规划 + 执行 |
| 预规划执行 | `python run.py .../cases/前审12-test.md --from-actions` | 读 `actions/` 跳过规划 |
| 批量跑目录 | `python run.py .../cases/` | 执行目录下所有 `.md` |
| 指定环境 | `python run.py ... --env-file .../project.env` | 覆盖本次 `.env` |
| 框架自测 | `pytest -m "not integration"` | 跳过需浏览器的集成测试 |
| 打交付包 | `python tools/export_handoff.py .../大学增加前审 --version v1.0` | 见 `business/delivery/` |
| HTTP 服务 | `uvicorn api.server:app --host 0.0.0.0 --port 8000` | 可选远程接入 |

## `business/` 业务资产

```
business/
├── <方向>/                         # 业务方向，如 tiku（可选层级）
│   │
│   └── <业务>/                     # 业务线，如 tiku_video、zbtiku
│       ├── .env / business.env     # 业务级环境（可选）
│       ├── domain_knowledge.md     # API、枚举、登录页（稳定）
│       ├── selectors/              # 智能加速（仅 cache/memory/structure 数据，无 manifest）
│       │   ├── cache/              # L1 短期缓存
│       │   ├── memory/             # L2 按 URL route 分文件
│       │   └── structure/          # L4 页面结构 → page_structure.json（见 docs/L4页面结构学习.md）
│       │
│       └── <项目>/                 # 项目名可中文，如 大学增加前审
│           ├── .env / project.env  # 项目环境 + 账号（不提交 Git）
│           ├── cases/              # 用例 Markdown（主真相源）
│           ├── actions/            # 动作规划（旧名 action_plans/）
│           ├── reports/            # 业务批次报告镜像
│           ├── resources/          # 测试资源（旧名 test_resources/）
│           ├── testsuites/         # 套件编排（预留，框架未接入）
│           └── delivery/           # 提测冻结快照
```

旧二层结构 `business/<业务>/<项目>/` 仍兼容（无方向层时 `direction_dir` 为空）。

环境合并顺序（后者覆盖前者）：`<方向>/.env` → `<业务>/.env` → `<项目>/.env` → 进程环境变量。

### `business/` 各目录执行方式

| 路径 | 执行时是否读取 | 执行方式 / 备注 |
|------|----------------|-----------------|
| `cases/*.md` | **是（入口）** | `python run.py <path/to/case.md>`；一个 md 可含多条用例 |
| `actions/<文件名>_actions.json` | 仅 `--from-actions` | 与 `cases/<文件名>.md` 一一对应；默认跑完覆盖写入 |
| `.env` / `project.env` | **是（自动发现）** | 跑用例时 `BusinessLoader` 合并加载；可用 `--env-file` 覆盖 |
| `domain_knowledge.md` | **是（自动发现）** | 业务层向上扫描；提供 API、登录页、枚举 |
| `selectors/` | **是（执行中更新）** | 定位加速 L1/L2/L4；执行后自动读写，交付包仅带 L2+L4 |
| `reports/<时间戳>/` | 否（输出） | 跑完后镜像 `report_overview.*` + `run_ref.json`；控制台打印此路径 |
| `resources/` | 用例引用时 | 用例 md 资源定义指向的附件路径 |
| `testsuites/` | **否（未实现）** | 预留批量编排；当前用 `run.py .../cases/` 跑整个目录代替 |
| `delivery/<version>/` | 否（交付物） | `tools/export_handoff.py` 生成；QA 提测验收用 |

#### 提测交付

```bash
# 默认自动附带最近匹配项目的 output/ui_runs 验收报告
python tools/export_handoff.py business/tiku/tiku_video/大学增加前审 \
  --version 20260625-v1.0

# 可选：指定批次 / 晋升规划 / 跳过验收
python tools/export_handoff.py business/tiku/tiku_video/大学增加前审 \
  --version 20260625-v1.0 \
  --batch output/ui_runs/20260625_170406 \
  --promote-plans
```

`delivery/<version>/manifest.yaml` 自动生成：项目与环境、各用例文件功能摘要、验收报告路径（`reports/<用例文件>.html`）。

详细约定见 [business/README.md](../business/README.md)。

## `core/` 框架内核

```
core/
├── agent.py                        # 总编排入口 UITestAgent
│
├── ports/                          # 与外部世界边界
│   ├── business/                   # 业务目录加载、env、交付包、plan_store
│   ├── output.py                   # 批次输出、业务报告镜像
│   ├── report.py                   # HTML / 批次报告
│   ├── codegen.py                  # Playwright 脚本生成
│   ├── observability.py            # 五级命中率、LLM 调用链
│   └── resources.py                # 测试资源路径解析
│
├── foundation/                     # 跨阶段基础
│   ├── layout.py                   # 目录与产物文件名常量
│   ├── llm/                        # LLM 适配、提示词加载
│   └── ...
│
├── pipeline/                       # 输入管线
│   ├── parser/                     # ① Markdown → ParsedCase
│   ├── preprocess/                 # ②③ 前置展开、排序
│   └── planning/                   # ⑥ 动作规划
│
├── understanding/dom/              # ⑧ 语义 DOM
├── locating/                       # ⑨ 五级定位链
│
└── runtime/                        # 执行与可靠性
    ├── session/                    # ④⑤ 登录、导航
    ├── readiness/                  # ⑩ 就绪检查
    ├── execution/                  # ⑪⑫⑬⑭ 分发、重试、Tab
    └── integration/                # 用例内 HTTP/API
```

旧 import 路径（`core.execution`、`core.planning` 等）通过兼容 shim 保留，新代码优先使用分层路径。由 `run.py` 间接调用，不单独执行。

## `prompts/` 策略配置

```
prompts/
├── planning/           # action_plan、precondition、case_sort
├── locating/           # element_decide
├── reliability/        # readiness、post_check、retry_plan
├── assertion/          # semantic_assert
```

优先级：`config.yaml` 内联覆盖 > `prompts/` 文件 > 代码内置兜底。跑用例时自动加载，提测后通常冻结。

## `output/` 运行时工作区

```
output/
├── ui_runs/<timestamp>/              # 每次测试批次
│   ├── report_overview.html/json     # 批次汇总报告
│   ├── playwright_suite.py           # 批次 Playwright 套件（静默生成）
│   └── <case_id>/                    # 单用例执行明细
│       ├── parsed_case.json
│       ├── planned_actions.json
│       ├── execution_trace.json
│       ├── observability.json
│       ├── execution_log.json
│       ├── prompts_used.md
│       ├── screenshots/              # 步骤失败时（step_NNN_fail.png）
│       └── semantic_dom/
│
└── prompt_replay/<timestamp>/        # tools/prompt_replay.py 输出
```

**失败截图**

| 场景 | 怎么看 |
|------|--------|
| 本地 | `output/ui_runs/<批次>/<case_id>/screenshots/` 直接打开 png |
| HTML 报告 | `report_overview.html` 或交付包 `reports/*.html`，失败步骤点 **「查看截图」** |
| 交付包 | `export_handoff` 会把截图复制到 `reports/<case_id>/screenshots/` |

默认 `runner.screenshot_on_failure: true` 时步骤失败自动截图。

不提交 Git，不进入 `delivery/` 交付包。

### `output/` 执行方式

| 路径 | 何时产生 | 用途 |
|------|----------|------|
| `ui_runs/<时间戳>/` | 每次 `run.py` 跑测 | 研发排查：定位链、LLM 调用、截图等全量明细 |
| `ui_runs/.../report_overview.*` | 批次结束 | 批次 HTML/JSON 报告（同时镜像到 `business/.../reports/`） |
| `prompt_replay/` | 手动执行 `tools/prompt_replay.py` | 从 observability 回放对比提示词 |

业务方看 `business/<项目>/reports/<时间戳>/`；研发深挖看 `output/ui_runs/<同时间戳>/`（`run_ref.json` 指向此处）。

## `api/` HTTP 接入

| 接口 | 执行方式 |
|------|----------|
| `POST /api/v1/ui-test/run` | 上传用例 md，走默认规划 + 执行 |
| `POST /api/v1/ui-test/run-preplanned` | 上传用例 + 动作序列，等同 `--from-actions` |

启动：`uvicorn api.server:app --host 0.0.0.0 --port 8000`

## `tools/` 辅助脚本

| 脚本 | 执行方式 | 作用 |
|------|----------|------|
| `export_handoff.py` | `python tools/export_handoff.py <项目路径> --version v1.0` | 打 `delivery/` 交付包（默认附带最近批次验收） |
| `prompt_replay.py` | `python tools/prompt_replay.py output/ui_runs/.../observability.json` | 提示词回放对比 |
