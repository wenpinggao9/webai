# L4 页面结构学习（`selectors/structure/page_structure.json`）

业务路径示例：

```
business/<业务>/selectors/structure/page_structure.json
```

对应框架里的 **L4**，和 L1 缓存、L2 记忆一起组成定位加速链。

---

## 一句话

**记住「这个路由上，这类控件一般用什么选择器模板」**，下次同页或结构相似的页，在不调大模型的情况下试着套模板。

和 L2 的区别：

| 层 | 记什么 | 键 |
|----|--------|-----|
| **L2** `memory/` | 某路由 + 某意图 → 具体 selector | `route + action + intent` |
| **L4** `structure/` | 某路由 + 控件类型 → **参数化模板** | `route + action_type + component_type` |

L2 是「这句 intent 上次点哪」；L4 是「这个页面上的按钮/输入框通常长什么样」。

---

## 文件里存什么

```json
{
  "version": 1,
  "saved_at": 1739...,
  "pages": {
    "/video/all-question": {
      "route": "/video/all-question",
      "component_library": "ant-design",
      "dom_signature": "d61534c80fe554de",
      "rules": {
        "click|button": {
          "action_type": "click",
          "component_type": "button",
          "selector_template": "role=button[name=\"{text}\"]",
          "selector_type": "css",
          "anchor_type": "text",
          "success_count": 1,
          "failure_count": 0
        }
      },
      "learned_at": ...,
      "updated_at": ...,
      "hit_count": 1
    }
  }
}
```

| 字段 | 含义 |
|------|------|
| `route` | 归一化 URL 路径（不含 query） |
| `component_library` | 页面组件库：`ant-design` / `element-ui` / `generic` 等 |
| `dom_signature` | 页面 DOM **结构指纹**（标签+role+类名前缀统计的 hash，不含具体文案） |
| `rules` | 规则表，key = `动作类型\|控件类型`，如 `click\|button`、`click\|generic` |
| `selector_template` | 参数化模板，如 `text="{text}"`、`role=button[name="{text}"]` |
| `success_count` / `failure_count` | 该模板成功/失败次数，用于置信度 |
| `hit_count` | 本页结构被 L4 **查中并复用** 的次数 |

---

## 在定位链里排哪

```
L1 缓存 → L2 记忆 → L3 规则/skill → L4 结构学习 → L5 大模型
```

- **L4 查找时机**：L1、L2、L3 都没给出可用 selector 时。
- **L4 查找方式**：
  1. **精确**：当前 `route` 在 `pages` 里有记录；
  2. **相似**：同 `component_library`，且 `dom_signature` 前 12 位一致的其他页。
- 命中后：用 `rules` 里的模板 + 当前 intent 抽出的 `{text}` / `{label}` 实例化 selector，并在 DOM 上校验候选是否存在。

---

## 什么时候会命中

需同时满足大致条件：

1. 该 `route`（或相似页）**以前成功定位过**，文件里已有规则；
2. 当前动作的 `action_type` 与某条 rule 一致（如 `click`）；
3. 该 rule 的 `failure_count` 没有明显高于 `success_count`（失败太多会被淘汰）；
4. 用 intent 抽出的文案能填进模板，且实例化后的 selector **在当前 DOM 上校验通过**。

**更容易命中的场景**

- 同一业务页反复跑（全部题目、待前审、详情页等）；
- 控件类型稳定（按钮、菜单项、通用 `text=` 点击）；
- 之前主要靠 L5 大模型定位成功，已回填进 L4。

**不容易命中的场景**

- 全新页面、从未跑成功过；
- 日期面板、复杂下拉、强位置语义（通常走 L3 skill 或 L5）；
- 页面大改版导致 `dom_signature` 变了（旧规则失效）；
- intent 文案与模板需要的 `{text}` / `{label}` 对不上。

---

## 什么时候会写入（学习）

**不是人工维护的文件**，由框架自动学习。

1. **学习触发**：任一层（L3 / L4 / L5）**成功**解析出 selector 后，`_backfill` 会调用 `learner.learn()`，把本次成功的 selector **模板化** 后 merge 进对应 `route` 的 `rules`。
2. **落盘时机**：每个 case 结束、整批跑完时 `agent` 调用 `learner.save()`，写入 `page_structure.json`。
3. **不会学习的情况**（与 L1/L2 类似守卫）：
   - selector 为 `body`、`TOAST_SEARCH` 等无意义值；
   - 宽松 `text=`（无引号）等易误匹配形式；
   - 部分日期控件、单选/复选弱 selector（见 `resolver._backfill`）。

**失败时**：L4 规则执行失败会 `record_failure`，失败次数过多会 **删除** 该条 rule。

---

## 日常怎么用（给 QA / 研发）

| 场景 | 建议 |
|------|------|
| 正常跑用例 | 不用管，跑多了会自动变厚 |
| 改版后定位变差 | 可删对应 `route` 节点或整文件，让系统重新学；或清 L1+L2+L4 一起重来 |
| 手工改 JSON | **不推荐**；模板格式和 `component_type` 推断有内部规则，改错反而误导 |
| 提测交付 | `export_handoff` 默认把 `selectors/structure/` 打进交付包（`config.yaml` → `delivery.accel.include_l4`） |
| 看有没有用上 L4 | 批次报告 / 控制台定位链里出现 `L4学习`；`hit_count`、`locating_stats` 里 L4 相关计数 |

## 和你项目里这份文件的关系

`tiku_video/selectors/structure/page_structure.json` 里已有例如：

- `/video/welcome`、`/video/all-question`、`/video/wait-preview`、`/video/detail` …

说明这些页面在以往跑测中，框架已经学过「Ant Design 页面上 click 按钮/通用文本」的模板。  
同路由再次执行、且 L1/L2 未命中时，会优先尝试这里的 `click|button`、`click|generic` 等规则，减少调 L5 大模型。

`hit_count: 0` 只表示**统计上 L4 查找路径还没记过一次命中**，不代表文件没用；规则仍可能在 `resolve_from_learned` 里被尝试。
