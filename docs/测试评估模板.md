# UI 自动化测试评估模板

一次测试工作填一张表，看两个数：**规划对不对**、**执行通不通**。

```
用例 md → 动作规划 → 评审是否对 → 执行 → 是否通过
              ↑ 规划正确率          ↑ 执行成功率
```

---

## 基本信息

| 项目 | 批次 | 评估人 | 日期 | 范围 |
|------|------|--------|------|------|
| | `output/ui_runs/<ts>` | | | 例：`前审12-test.md` |

---

## 核心指标

| 指标 | 算法 | 数据从哪来 |
|------|------|------------|
| **动作规划正确率** | 评审为「正确」的 case 数 ÷ 评审 case 数 | 对照 `actions/*.json` 或人工看规划结果 |
| **用例执行成功率** | 通过 case 数 ÷ 执行 case 数 | 批次报告 `report_overview.json` / `reports/*.html` |
| **步骤执行成功率**（可选） | 通过步骤数 ÷ 总步骤数 | 同上，汇总各 case 的 `passed_steps` |

**规划评审**：✅ 正确 / ⚠️ 有小问题可修 / ❌ 错误（漏步骤、错类型、缺断言等）

**执行失败归因**：规划问题 / 定位 / 后校验 / 环境数据

> 规划错了导致跑挂，记规划问题，别全算执行能力差。
